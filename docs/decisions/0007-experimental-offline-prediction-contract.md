# ADR 0007: Explicit offline artifacts and experimental prediction policy

Status: accepted for M01.

## Context and options

EXP-003's frozen B_RF-01 improves MAE on one validation period; EXP-004/005 show
inconsistent temporal and department gains. Feature capture timestamps, label
finalization, production grain and freshness requirements remain unverified. An
offline interface must expose these limits before any planning integration.

Options were implicit retraining per request, an HTTP service, or explicit local
artifact generation followed by separate inference. Choose the last: the other
options obscure model lineage or expand this milestone's scope. Reuse dataclasses,
pandas, the existing forest/feature pipeline and department baseline. No new
dependencies, model search, factories or persistence services are needed.

## Decision

Use strict versioned request/result dataclasses with closed JSON fields. Reject
malformed inputs rather than applying historical CSV normalization to requests.
Scheduled date, canonical department and categorical team are the only source
model fields. Weekday and day of month come from that date. Provenance, cutoff
and optional shift ID are validation metadata, not additional predictors.

Separate contracts, review policy, artifact management, pure inference and CLI in
`loometric.prediction`. Keep existing experiment APIs and commands unchanged.
Training is an explicit command, never an inference fallback. Freeze B_RF-01 at
100 trees, depth 3, leaf size 20, random_state 42 and n_jobs 1 with existing features.
Fit and store Department Mean on the same training records.

For this artifact path, verify source bytes against the frozen split before
reading dates. Verify complete dates and row counts with existing splitting logic.
Use source row ordinals to retain and normalize/validate **training records only**
in the second CSV pass. CSV bytes and structure are scanned, but outer labels and
non-date features are not retained, normalized, validated, fitted or evaluated.
All original training validation checks remain; the older full-source experiment
loaders retain their behavior. Do not regenerate the frozen config or use either
outer partition to select or score anything in M01.

Persist the fitted sklearn Pipeline with the already pinned joblib dependency.
Record configuration, feature/input versions, training lineage, baseline, learned
categories, environment and model-byte hash in canonical JSON. Return the manifest
fingerprint from training; require that separately retained trusted digest at load.
Verify digest, versions, configuration, environment, lineage and model bytes before
deserialization; check loaded estimator/preprocessing metadata afterward. Require
an exact environment match and refuse directory overwrite. Exclude volatile times
from artifact identity so deterministic generation is testable. Store artifacts in
the existing ignored `data/processed/` path; do not change ignore rules.

Joblib is pickle-based and can execute code. This design permits only artifacts
generated by the trusted local code, with a digest retained outside the artifact
directory. Checksums detect changes; they do not authenticate a publisher or make
untrusted pickle safe. ONNX/skops would add dependencies/conversion and are deferred
until a concrete distribution boundary justifies them. See the primary
[sklearn persistence guidance](https://scikit-learn.org/stable/model_persistence.html).

Return VALID_EXPERIMENTAL, REVIEW_REQUIRED or ABSTAIN. Unknown teams always require
review or explicit configurable abstention. Missing/incompatible artifacts, invalid
contracts, inconsistent provenance, future snapshots, passed cutoffs, temporal
overlap with training, or evidence-defined stale snapshots cause abstention. No
numeric freshness limit is guessed: a configured limit needs a source binding and
documented evidence reference. Evidence references are caller assertions, not
software verification of operational facts. Missing timing/freshness evidence
requires review. Predictions above one remain visible with a warning, never clipped.

Every status remains experimental, requires human review and forbids automatic
staffing, scheduling or production authorization. No uncertainty interval is supplied.
VALID_EXPERIMENTAL means configured contract checks passed, not production readiness.
An explicit offline replay reference time is allowed for deterministic synthetic
acceptance cases; mark it as replay, require review and return actual execution time
separately. Never relabel replay time as actual execution time.

## Consequences and limits

The future API can reuse the contract/policy/inference boundary without owning
training. No endpoint, database, UI, scheduler, monitoring service or deployment is
introduced. A valid request proves syntactic consistency only; it cannot prove that
an assignment was known before a real shift. Timezone offset and source IDs are
caller supplied. Shift start, label latency, roster identity and productivity units
still need factory evidence. Fixed 2015 data do not validate forecasts for later
years or a new factory. Preserve EXP-001 through EXP-005 without promoting the forest.

Synthetic tests protect train-only preprocessing, outer-label isolation, frozen
splits, deterministic artifacts/inference, integrity-before-deserialization,
baseline comparisons, unknown/stale inputs and abstention. Keep raw records,
generated binaries/receipts and local engineering instructions out of commits.
