# ADR 0015: Local dashboard, exact presentation and explicit data provenance

Status: accepted for M06A before frontend implementation and browser verification.

Use an isolated frontend/ package with React, strict TypeScript and Vite. Choose
plain CSS tokens and semantic native controls rather than a large component/theme
framework. Native hash routing supplies five inspection pages without a server
rewrite, API proxy or router dependency. Use small context/hooks only for session,
dataset and report ownership, not a global state framework. Biome handles JS/TS/CSS
format/lint; Vitest/Testing Library and Playwright/axe cover components and real HTTP.
Pin direct versions and commit the npm lockfile; retain Python dependencies unchanged.

The dashboard is a client of existing M05A contracts. Capacity arithmetic, calendar
unions, feasibility, schedule verification and all ML/solver work stay in Python.
No backend/catalog changes, dispatch/optimizer controls or interactive what-if work.
M06B is separate. Existing scheduling proposals may be explicitly loaded/read and
verified through the existing endpoint; no schedule is generated by the UI.

Read the exact existing synthetic fixture text through a small explicit catalog.
Bundled report snapshots come from the frozen Python engines and are separately
labelled fixture preview, never live API responses. These small, intentionally
versioned golden test fixtures are not runtime exports, model artifacts or source
datasets. Browser tests compare them to
actual responses. Switch input -> discard prior report/schedule ownership; late
responses must not overwrite a different dataset/session. Failed live requests show
errors, never a silent demo fallback. No claimed live factory monitoring or ML API.

Use lossless-json to retain numeric input tokens and encode planning decimals as
JSON numbers. Presentation models use exact decimal/integer strings, with BigInt
only for count totals, exact unit-preserving report sums and bounded visual ratios.
Never convert productivity/capacity/efficiency values through Number. Integer pixel
widths may be explicitly quantized for layout; exact text remains visible. Charts
trace to unique report slots, not repeated independent order assessments. Stage
capacities are not interchangeable, M02 is not a global production plan, and
utilization exists only when a verified schedule is explicitly loaded.

Source-text identities use SHA-256 over UTF-8 JSON with LF line endings so Windows
Git line-ending conversion does not change their identity. This presentation-only
identity does not replace or modify any existing dataset/split/instance fingerprint.
Original input files are imported directly and remain byte-for-byte unchanged.

The supported dev/preview origin is 127.0.0.1:5173, matching existing restricted CORS.
Allow only a configured literal HTTP loopback API origin; no proxy, remote hosts,
credential URLs, analytics, CDN fonts or external assets. Bearer token stays in
memory, never localStorage/sessionStorage/URL/environment bundle/logs. Disconnect
aborts requests and clears the configured secret. Local files are not server paths.
The Vite filesystem allowlist excludes raw data/artifacts/local engineering files.

Use a light, responsive manufacturing workspace with persistent synthetic/source
labels, semantic navigation, focus management, keyboard controls, status text beyond
color, accessible tables, units, assumptions and explicit empty/loading/error states.
Accessibility smoke results are evidence for tested views, not a conformance claim.
Only local development/build artifacts are produced; no publishing or deployment.
